# Multi-tool: durable traps

Every one of these was measured while doing this track's work. A trap here is a thing that will
cost an hour again if it is not read first.

| id | The hazard, and what it costs | Anchor |
|---|---|---|
| MT-01 | The env guard denies a Write whose BODY spells the guarded secret filename, including a quoted docs example or a `permissions.deny` entry. Both research agents lost a write to it on 2026-10-05. A registry row or fixture quoting another tool's deny example will hit it: describe the entry, do not spell it | `scripts/harness/guards/env-guard.cjs:224` |
| MT-02 | Every fact about a non-Claude tool came through a summarising fetch and no tool was run. Hook field names, exit codes and nested loading are paraphrase. Code built on a row is built on `docs` evidence until someone runs the tool | `docs/tracks/multi-tool/research/2026-10-05-tool-instruction-surfaces.md` |
| MT-03 | The config is closed twice: an unknown top-level key is a hard error in the loader AND the schema refuses additional properties. Adding `tools` in one place only fails every gate with a config stop, which reads like a broken suite | `scripts/harness/config.js:344` |
| MT-04 | One test reads the real settings file, requires every registered hook command to be the one entry, and RUNS it once per guard per kind of call (shell, file, search, MCP), each payload chosen so only that guard refuses. Any change to the registration, the matcher or a handler's `actions` list reds it even when the guards are right; the same block pins a floor on how many commands the file holds | `tests/guards.test.js:836` |
| MT-06 | The re-arm check grades the settings deny list only for a row whose `hookConfig` IS the file its dialect names as the permissions file. Every other row gets no deny-layer check at all, and two rows share the claude dialect without sharing that file. Re-shaping the settings file, or pointing a row at it, silently turns the session-start warning into a false alarm or a false all-clear. The env guard's own `--rearm-check` keeps a second, separate read of the same file | `scripts/harness/hook.js:94` |
| MT-07 | A subagent spawned inside a running session holds the instruction files as they were when that session STARTED. A change to `CLAUDE.md` or `AGENTS.md` can only be probed from a new session (`claude -p` at the repo root); a probe from the session that made the edit reports the old files and reads like a failed import | `CLAUDE.md` |
| MT-08 | A second session works in this same uncommitted tree. A blanket `git add -A` stages its files along with yours, and one did on 2026-10-06. Stage by path, and never stash, restore or reset here | `scripts/harness/mode.js` |
| MT-09 | The doc gate and the context gate now require `tools.js`, which loads `tools.json`. A fixture repo that copies a guard without both dies on the require, which reads like a broken guard | `tests/lifecycle.test.js:637` |
| MT-10 | The byte ceilings of `AGENTS.md` and the routing doc were carried over with only a few percent of headroom, under the budget file's own rule. A one-paragraph policy edit reds the `context` gate with nothing actually wrong | `scripts/harness/context-budget.json:83` |
| MT-11 | Three tests pin the claude-code registry row: one its evidence value, one four phrases of its notes, and one in `tests/hook.test.js` that every row wired to a dialect is still `docs`. Editing that row's evidence or notes without rewriting all three reds the suite, so a promotion to `ran` is a code change, not a data edit | `tests/tools.test.js:495` |
| MT-13 | The `files` globs in the package manifest are one level deep and one extension wide: the entry for the harness scripts ships neither a subdirectory nor a `.cjs`. The guards and the dialects each needed their own entry. Any new directory of modules needs one too, and nothing reds without it: the installer copies recursively from a checkout, so only a packed install is short | `package.json:46` |
| MT-14 | The branch-sync fixture uses `.claude/helpers` and `scripts/harness` as two INDEPENDENT mirrored directories. Repointing the first to the guards directory nests it under the second and changes what every only-this-reds case reds: a meaning change that reads like a path fix. Leave the fixture; a clean grep needs a redesign with a non-nested second directory | `tests/branch-sync.test.js:84` |
| MT-15 | The helper that drives a guard over stdin asserts exit status 0 on every call, and several fixtures pin an `ask`, a third outcome beside deny and allow. A guard CLI that starts exiting 2 on a deny, or a verdict type with no way to say ask, reds or silently rewrites those fixtures. Exit 2 belongs to the one hook entry, not to a guard run directly | `tests/guards.test.js:125` |
| MT-16 | Three dialects (gemini, cursor in part, antigravity) carry no table from the tool's own tool names to the neutral action, because the research cells give none. Every call there is opaque, an unreadable opaque call is an ask, and those dialects spell an ask as a deny. Wired as written they refuse ordinary work; the fix is running the tool and adding the table, not loosening the guard | `scripts/harness/dialects/gemini.js:16` |
| MT-17 | The pre-tool matcher is the union of the tool names the guards decide on, not match-all. The claude dialect marks any name it has no row for as opaque and the phase guard asks about an unreadable opaque call, so widening the matcher turns every web fetch, task or todo call into a prompt. A session also keeps the hooks it started with: a change to this file is only proven from a new session | `.claude/settings.json:7` |
| MT-18 | The hook entry refuses, with exit 2, any command line that is not exactly a tool id plus an event: no arguments, a doubled flag, or a help or self-test flag beside the others. That is deliberate (a flag appended to a registration must not switch it off), so a rendered registration with one token wrong denies every call on that tool, which reads like a broken guard | `scripts/harness/hook.js:718` |
| MT-20 | A hook config is rendered only for a row whose `hookConfig` is the file its dialect's `wiring` export names, and two dialects export one. The research gives no shape for the Codex or Antigravity hook file, and the Gemini dialect cannot read a call, so enabling those tools writes no hook file: `init` and `doctor` say so in a NOTE, which reads like a bug in the installer. The fix is running the tool and adding a `wiring`, never a shape typed from memory | `scripts/harness/wire.js` |
| MT-21 | On a machine with no auto-memory index the doc gate reports one skipped check, so the plain exit command is red there before any edit; measured on 2026-10-07. Tolerate it by name beside the build skip (`docs=1`), and do not create an index to make it pass | `scripts/harness/guards/docs-lint.cjs` |
| MT-19 | Doctor finds a missing guard by following the registered hook script's literal relative requires one level, and a test pins the resulting line. A guard loaded through a computed path, or a second level down, is invisible to it; and doctor still opens only the one Claude settings file | `tests/cli.test.js:304` |
